# Agent Work OS｜模型切换与项目记忆 v1.0

> 用途：让 Codex 在切换模型、重开会话、压缩上下文或移交到另一 Agent 后，仍能从项目仓库恢复一致的目标、当前状态与实施约束。**不代表自动共享不同平台的聊天记忆。**

## 如何安装到正在开发的项目

1. 将本包的 `agent-memory/`、`prompts/` 和 `qa/` 文件夹**合并**到当前 Codex 项目根目录；若同名文件已存在，先对比再合并，不要覆盖真实进度。
2. 读取 `AGENTS_追加片段_勿直接覆盖.md`，把其中标记区域追加到项目**现有**的根目录 `AGENTS.md` 末尾；如果已有等价规则，合并去重即可。不要用本包代替你原来的 AGENTS.md。
3. 将现有本地验收报告 `P1_CODEX_LOVART_ACCEPTANCE.md` 保留在原位置（若报告实际不在根目录，修改 `agent-memory/04_EVIDENCE_INDEX.md` 为真实路径）。
4. 切换模型或新建 Codex 会话后，粘贴 `prompts/新模型接班指令.md` 的内容。
5. 每次阶段结束或切模型之前，运行 `prompts/切换前交接指令.md`：让 Codex 更新 `01_CURRENT_STATE.md` 与 `03_NEXT_ACTION.md` 等文件并注明证据，避免下一个模型误从旧任务开始。

## 最关键的三件事

- **目标真相源**：`agent-memory/00_PROJECT_BRIEF.md`——我们要做什么、不做什么。
- **状态真相源**：`agent-memory/01_CURRENT_STATE.md` + 原始报告——现在实际通过哪些验收。
- **下一步真相源**：`agent-memory/03_NEXT_ACTION.md`——下一轮只做什么、何时停止。

`AGENTS.md` 是给 Codex 的**引导索引**；其他文档是详细内容，不要把整个历史聊天硬塞进 AGENTS.md。

## 对所有模型的限制

模型可能对同一工具的支持、上下文窗口、调用格式存在差异。能读取项目文件并不等于能安装到 Codex，也不代表一定能操作 Windows、Playwright 或网页。先验证模型和工具可用性，不能将“读懂文件”误写成“可执行”。

不要把 API Key、浏览器 Cookie、登录令牌、完整账号个人信息、授权回调 URL 写入任何交接文件或 Git 仓库。项目应优先保留本地文件、截图路径、脱敏日志和验收结果。
