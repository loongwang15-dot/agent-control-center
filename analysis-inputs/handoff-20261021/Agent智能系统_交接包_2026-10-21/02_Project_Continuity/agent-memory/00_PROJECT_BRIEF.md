# Project Brief｜长期不变的项目目标

版本：v1.0 · 初始整理日期：2026-10-20 · 所有实际状态以最新报告为准。

## 最终产品愿景

构建一套**能直接替用户工作的 Windows 本地 Agent 联动体系**：用户向 Codex 下达任务，Codex 根据任务选择已有的 AI 软件/网页/Skill，完成指令发送、参考素材上传、结果读取、质检、文件下载与归档。

不是要求重新开发一个多模型聊天平台。用户强调的能力是：**控制已有的软件/网页中的现成 Agent**，而不仅仅是调用等价的大模型 API。

## 首选控制方式（从稳定到脆弱）

1. 目标软件已有经过授权的正式 Agent / 本地接口：优先使用，维持同一软件的完整功能（需核实授权与调用边界）。
2. 网页有登录会话：优先使用微软官方 Playwright MCP 及标准浏览器事件，复用可控会话；不得未经核实声称一定能复用浏览器 Profile。
3. 仅有 Windows GUI：研究 Windows UI Automation/MCP，验证元素是否可定位及是否稳定。
4. 不为此重写目标 AI 软件。必要时开发最小适配，不能新建一个替代整个平台的系统。

## 近期验收序列（按阶段）

- P1-A：Codex + Playwright MCP → Lovart 网页文件上传 → 取得授权后测试生图、下载。
- P1-B：在相同浏览器控制底座上接入即梦，并按网站实际页面检验。
- P1-C：DeepSeek/豆包（网页或桌面）与 WorkBuddy 等已有 Agent 能力接入；优先正式支持的接口。
- P2：不同平台之间的任务委派、成果回传、统一归档、异常恢复。
- P3：再按实际需要增加 AgentScope/其他可视化编排、调用链监控。

## 历史探索（不要混为当下任务）

Agent Work OS v1.0/v1.1 的全栈架构、AgentScope 2.0 可视化，以及 OpenClaw + DeepSeek 父子 Agent 真实调用均是已经探索过的方向和资产。**当前 P1-A 不是继续改造 OpenClaw，亦不是再开发新 UI。**

## 守则

真实结果优先；可移植、最小修改、保留已有配置；账号登录、密钥、积分消耗和无法验证的操作都要控制权限。
